Vercel 部署 LINE 小秘書：
每一步按哪裡

講師的 LINE 小秘書是開源的：Fork 一份、填幾把鑰匙，就是你自己的。這一頁假設你從來沒用過 Vercel，從複製程式碼一路帶到提醒準時跳出來。右邊示意圖的紅框和號碼就是要按的地方。

示意圖是簡化過的畫面，不是真的截圖；平台偶爾會改按鈕的名字或位置。小秘書自己的 README 有真的截圖，兩邊對照著看。

這一頁只帶你點「平台的按鈕」。申請帳號、登入、按「建立」這些事一定要你本人做。真正改程式的部分（改口氣、加功能、找錯誤），交給 Claude Code：每一步都附一句「卡住時對 Claude Code 說」，你負責把狀況講清楚、最後自己驗收。

00
開始之前

先認識 5 個名詞

看不懂也沒關係，做的時候回來查。

Fork在 GitHub 上把別人的專案「複製一份到你的帳號」。之後你改你的，不會動到講師的。
Vercel放程式的雲端平台。你的 GitHub 一有新版本，它就自動重新部署（單元 05）。
環境變數放鑰匙的地方。程式裡只寫鑰匙的名字，值只填在 Vercel 的設定裡（單元 06）。
Redeploy重新部署。改了環境變數一定要 Redeploy，新的值才會生效。
cron-job.org免費的鬧鐘服務：每 5 分鐘叫小秘書檢查一次有沒有要提醒的事。
要準備：GitHub 帳號、Google 帳號、大約 40 分鐘，以及一個記事本，裡面已經有 LINE 的兩把和 Supabase 的兩把鑰匙： 
LINE_CHANNEL_SECRET=
LINE_CHANNEL_ACCESS_TOKEN=
SUPABASE_URL=
SUPABASE_SERVICE_KEY=
GEMINI_API_KEY=（第 2 步拿）
DASHBOARD_TOKEN=（自己取一組後台密碼）
記事本存在自己的電腦就好，不要存到雲端共用資料夾、不要傳到 LINE。
01
一步一步

讓小秘書上線

每做完一步，勾一下「我做完了」，下次回來就知道做到哪。

1Fork 講師的小秘書

  1. 登入 GitHub，打開 github.com/windsjp00171-star/line-secretary-
  2. 右上角按 Fork ①
  3. Repository name 可以改成你喜歡的 ②，按 Create fork ③

你的 GitHub 會多一份一模一樣的程式碼。之後用 Claude Code 改的，就是這一份。

⚠️ Fork 出來的專案是公開的。沒關係：鑰匙不在程式碼裡。但也因為公開，之後絕對不能把鑰匙寫進任何檔案。

🤖 卡住時對 Claude Code 說：「Fork 和直接下載程式碼有什麼不一樣？Fork 出來的專案是公開的，我要注意什麼？」

2拿 AI 金鑰（免費的 Gemini）

  1. 打開 aistudio.google.com/apikey，用 Google 帳號登入
  2. 按 Create API key ①（第一次會要你同意條款）
  3. 複製那串金鑰 ②，存到記事本標上 GEMINI_API_KEY=

免費額度對一個人用很夠；每天額度用完時小秘書會主動告訴你，隔天自動恢復。

⚠️ 依 Google 條款，免費方案送出的內容可能被拿去改進 Google 的產品，也可能有人工審閱。練習時記買菜、喝水沒問題；要記個資、公司或教會內部的事，改用付費層（單元 12、21）。

🤖 卡住時對 Claude Code 說：「Gemini 免費方案和付費方案，對我送出去的資料有什麼差別？我想用小秘書記＿＿，適合免費方案嗎？」

3在 Vercel 填鑰匙、部署

  1. 打開 vercel.com/new，選 Continue with GitHub 登入
  2. 在 Import Git Repository 找到第 1 步 Fork 的專案，按 Import ①
  3. 展開 Environment Variables ②，把記事本的 6 組一組一組加進去：Key 填左邊的名稱，Value 貼上值 ③
  4. 按 Deploy ④，等 1 分鐘左右看到煙火 🎉
  5. 按 Continue to Dashboard，上方 Domains 那串（例如 https://my-secretary.vercel.app）就是你的小秘書網址，也存到記事本
⚠️ Key 的名稱大小寫、底線一個字都不能錯，前後不要多空白。
⚠️ SUPABASE_SERVICE_KEY 要貼 Supabase 的 secret（service_role）那一把，不是 publishable。

🤖 卡住時對 Claude Code 說：「請讀這個專案的 .env.example，用白話告訴我每一個環境變數是做什麼的、值要去哪裡找、哪些是秘密。只列名稱，不要叫我把值貼給你。」

4打開設定精靈，把每一項變綠色

  1. 瀏覽器打開 你的網址 + /setup.html，輸入你取的 DASHBOARD_TOKEN ①
  2. 精靈會逐項檢查：環境變數、LINE 連線、Webhook、資料庫、主人、AI、圖文選單、提醒排程
  3. 第 3 張卡按 一鍵設定 Webhook ②（LINE 那邊就接好了）
  4. 資料庫是紅色：按「複製建表 SQL」→「打開 SQL Editor」→ 貼上 → Run（圖解：Supabase 第 3 步）
  5. 第 7 張卡按 建立圖文選單 ③，聊天室下方就會出現按鈕
  6. 改完任何設定，按 🔄 重新檢查 ④

「主人」和「提醒排程」是接下來第 5、6 步；其他卡片綠了就可以往下。

🤖 卡住時對 Claude Code 說：「設定精靈的第＿張卡是紅色，上面寫：（貼上說明文字）。請讀 api/setup/status.js，用白話告訴我它在檢查什麼、我要去哪裡改。」

5設定主人（只有你能用），然後 Redeploy

  1. 用手機加小秘書好友，傳任何一句話；它會回你一串 U 開頭的 userId（圖解：LINE 第 8 步）。設定精靈第 5 張卡也會出現，可以直接複製
  2. Vercel → 你的專案 → Settings ① → Environment Variables ② → 新增 Key LINE_USER_ID，Value 貼上 userId ③ → Save
  3. 到 Deployments，最上面那一筆右邊的 ⋯ → Redeploy ④

設好主人之後，別人就算加了好友、傳訊息，它也不理、不寫進資料庫、不會用掉你的 AI 額度。

⚠️ Vercel 的環境變數要重新部署後才會生效。之後只要改了任何一個，都要 Redeploy 一次。「改了沒反應」八成是忘了這步。

🤖 卡住時對 Claude Code 說：「我設了 LINE_USER_ID 也 Redeploy 了，小秘書還是回我 userId。請讀 api/webhook.js，告訴我它怎麼判斷誰是主人，我該檢查哪裡。」

6讓提醒準時跳出來（cron-job.org）

  1. 先到 Vercel 新增環境變數 CRON_SECRET，值隨便打 20 個以上的英數字（排程的暗號），然後 Redeploy
  2. 到設定精靈第 8 張卡，按「複製」拿到排程網址 ①
  3. 打開 cron-job.org 免費註冊並登入，按 CREATE CRONJOB ②
  4. Title 填「小秘書提醒」；URL 貼上剛剛的網址；Execution schedule 選 Every 5 minutes ③ → CREATE
  5. 5 分鐘後回設定精靈按「重新檢查」，第 8 張卡變綠色就完成了

為什麼要另一個平台？Vercel 免費方案的排程一天只能跑一次，只夠發早安簡報；提醒要每 5 分鐘檢查一次，才交給 cron-job.org。

⚠️ 排程網址裡有你的暗號，不要貼到公開的地方。外洩了就換一組 CRON_SECRET、Redeploy，再更新 cron-job.org 的網址。

🤖 卡住時對 Claude Code 說：「請讀 vercel.json 和 api/cron/remind.js，用白話告訴我哪些排程是 Vercel 跑的、哪些要靠 cron-job.org，時間各是台灣幾點。」

7出問題時，去哪裡看錯誤

  1. Vercel → 你的專案 → 上方的 Logs ①
  2. 在 LINE 再傳一句話，這裡會多出一行 /api/webhook ②
  3. 紅色的就是錯誤 ③。先把裡面的鑰匙、權杖換成 xxx，再截圖或複製給 Claude Code 或講師

小秘書不回話，先看這裡有沒有出現紀錄：沒有紀錄是 LINE 沒把訊息送來（Webhook、回應設定）；有紀錄但是紅色是程式或鑰匙的問題。

🤖 卡住時對 Claude Code 說：「這是 Vercel 的 Logs（金鑰已經換成 xxx）：（貼上）。請用白話告訴我哪裡出錯、我下一步該檢查什麼。」

8接收講師的更新

  1. 到你 GitHub 上 Fork 的那一份，按 Sync fork ①
  2. 按 Update branch ②，Vercel 會自動重新部署
  3. 想完全自動：Actions 分頁 → 按 I understand my workflows, go ahead and enable them，之後每週自動合併

講師推出新功能或修好問題，你按一下就跟上。更新說明寫「需要更新資料表」時，再到 Supabase 執行一次最新的 schema.sql（重複執行不會影響已有的資料）。

⚠️ 你自己改過的地方如果剛好和講師改到同一處，同步會失敗，GitHub 會寄信通知你，你的程式不會被弄壞。這是「自己維護一份」的代價：改得越多，跟上更新越要花力氣。

🤖 卡住時對 Claude Code 說：「我按 Sync fork 出現衝突（conflict），請用白話說明是哪個檔案、我的版本和講師的版本各改了什麼，建議怎麼合併。先不要動手。」
