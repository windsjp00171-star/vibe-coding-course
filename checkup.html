01
適合誰

做得出來，不代表放心交出去

🛠️ 同仁自己用 AI 做工具

行政、業務、老師用 Claude Code 或 ChatGPT 做了內部系統。最常見的事故是金鑰寫在程式裡、資料表沒上鎖、頁面沒登入也能進。

🤝 找外包做的系統要驗收

對方交了程式，你看不懂也不知道從何問起。健檢報告把問題翻成白話，驗收時有東西可以對照。

🎓 學校、社團的學生專案

學生作品要上線給真人用之前，先過一次健檢；報告也是很好的教材。

02
怎麼進行

三步，用你們自己的程式上課

① 事前健檢

貼一個連結授權指定的專案（只能讀、不能改），用 RepoDoctor 產出健檢報告。講師先看過，挑出最需要談的幾個問題。

② 半日工作坊

不用假範例，用你們自己的報告上課：金鑰外洩、資料表權限、登入與權限。每個問題都有寫好的修復指令，當場貼給 Claude Code 一起修。

③ 一個月後複檢

再健檢一次，交一份對照報告：分數升了多少、修好幾個、還剩哪些、下一步先做什麼。

03
帶走什麼

不是聽完就算了

📊 改善前後對照報告

分數變化與修好的問題清單，用白話寫，可以直接交給主管或董事會。

🧾 每個問題的修復指令

要改哪裡、不能動什麼、怎麼驗證，貼給 Claude Code 就能修。沒來上課的同仁也用得上。

📏 團隊的 AI 寫程式規則

一份放進專案的 CLAUDE.md：以後 AI 寫程式會照著做，同樣的問題不會再出現。

04
程式碼怎麼處理

我們看得到什麼、留下什麼

  • 只申請唯讀權限，而且只看得到你指定的專案；不能修改、不能開 PR。
  • 健檢時程式碼下載到臨時主機，健檢結束立刻刪除，我們的資料庫裡沒有你們的程式碼。
  • 報告只有貴單位看得到；裡面的金鑰只留前 4 碼。問題細節保存 90 天後自動刪除。
  • 隨時可以在 GitHub 收回權限，或刪除所有資料。

06
常見問題

主管會問的幾件事

會不會改到我們的程式？

不會。授權只有「讀」的權限，GitHub 不允許我們修改、開 PR 或刪除任何東西。修改永遠是你們自己的同仁在工作坊裡動手。

我們的程式不在 GitHub 上可以嗎？

目前只支援放在 GitHub 個人帳號下的專案；放在 GitHub 組織帳號或其他平台的，洽詢時告訴我，我們一起找可行的做法。

同仁不太會寫程式，跟得上嗎？

工作坊的對象是「有在用 AI 做東西」的同仁，不需要會寫程式。報告和修復指令都是白話，修的動作交給 Claude Code。

可以先自己試試看嗎？

可以。RepoDoctor 的規則掃描免費，登入 GitHub 就能先健檢一次；看完報告想請講師帶著修，再來洽詢。
