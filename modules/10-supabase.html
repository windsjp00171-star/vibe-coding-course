10 C 存資料

資料要放在哪？
誰看得到？

報名、請假、借設備、訂便當……上班族想做的工具，大多要「把大家填的東西存起來」。這個單元從最根本的問題開始：資料到底要放在哪、長什麼樣、誰可以看。最後用講師準備好的範本，做出一個真的有登入、有門禁的登記系統。

  • 判斷資料該放在瀏覽器、Google 表單，還是資料庫
  • 把自己的題目畫成一張表，說得出誰能看、誰能改
  • 用範本建好有門禁（RLS）的登記系統，並用第二個帳號驗證
  • 分清楚可以公開和絕對不能公開的金鑰
課前自學 約 25 分 課中工作坊 約 150 分 課後任務 約 20 分
01

資料要放在哪？不一定要用資料庫

很多人一想到「存資料」就要架資料庫。其實先問兩個問題：誰要看得到？需不需要登入？

放在哪適合例子缺點
🖥️ 使用者自己的瀏覽器只有自己用，資料不用給別人看個人記帳、報表整理器、計算機換台電腦就不見；別人看不到
📝 Google 表單＋試算表只是要「收」大家填的東西，主辦人一個人看聚餐調查、活動回條填的人看不到自己填過什麼；很難做登入、分權限
🗄️ 資料庫（Supabase）要登入、每個人看自己的、管理者看全部、還要改狀態設備借用、請假、報名審核、訂單要設定權限，設錯就會外洩（這個單元教你怎麼設對）
先用最簡單的方法。Google 表單做得到的，就用 Google 表單；需要「每個人看自己的、有人審核、狀態會變」，才用資料庫。知道什麼時候不用寫程式，也是導演的能力。
02

資料庫跟 Excel 哪裡一樣、哪裡不一樣？

Excel資料庫（Supabase）
長相工作表、欄、列資料表、欄位、一筆一筆資料，概念一模一樣
放在哪你的電腦或雲端硬碟雲端，網站和 App 隨時都能讀寫
多人同時用容易互相蓋掉幾千人同時報名也不會亂
誰能看拿到檔案就全部看得到可以規定每個人只能看某幾列（RLS）
規則靠大家自律可以規定「電話一定要填」「狀態只能是這三種」
Supabase 是什麼？一個幫你準備好「雲端資料庫＋會員登入＋檔案儲存」的服務，免費方案就能開始用。講師的報名系統、靈修日記、LINE 小秘書，還有這個課程網站的會員功能，都是用它做的。
03
紙上練習

把你的題目畫成一張表

動手之前，先在紙上畫：一列是什麼？（一次借用、一張假單、一筆訂單）有哪些欄位？（每一欄要填什麼）

例子：設備借用

姓名要借的設備使用日期備註狀態
王小明投影機10/1—待處理
陳美美筆電10/2會議用已確認

「狀態」和「時間」範本已經幫你準備好了，你只要決定前面那幾欄。

三個好習慣

  • 只收用得到的：用不到的欄位不要收，尤其是身分證字號、生日、住址（單元 21）
  • 能選就不要打字：葷素、部門、設備用下拉選單，資料才整齊
  • 欄位名稱用白話：之後匯出給主管看，一看就懂

06
      
哪一把可以放在網頁上？

    

      
可以公開
🪪 Publishable key（訪客證）
以 sb_publishable_ 開頭（舊版叫 anon key）。放在網頁上沒關係，因為拿著它能做什麼，完全由 RLS 規則決定。

      
絕對不能公開
🗝️ Secret／service_role key（萬能鑰匙）
拿到它就能跳過所有 RLS，讀寫刪除全部資料。只能放在伺服器的環境變數裡，永遠不進網頁、不進 GitHub、不貼給任何人。

課中．約 150 分（中間休息 10 分）

      
    
        
  1. 0–25 分在紙上把你的題目畫成一張表（第 03 段），再照第 05 段填一張權限矩陣。組員互相問：這個欄位真的需要嗎？這個人真的要看得到嗎？
    2. 
        
  2. 25–40 分下載範本、解壓縮，用 Claude Code 打開資料夾，請它「讀 README.md 和 CLAUDE.md，用白話跟我說這個專案在做什麼」。
    3. 
        
  3. 40–75 分照 README 的五步設定：建 Supabase 專案、貼 setup.sql、填網址、填鑰匙、push 上線。卡住就把錯誤訊息貼給 Claude Code，先把鑰匙換成 xxx。
    4. 
        
  4. 75–100 分用你的 Email 登入，新增兩筆；到 Supabase 的 Table Editor 看資料真的進去了。
    5. 
        
  5. 100–125 分門禁測試：用第二個 Email 登入（或請組員登入），確認看不到你的資料、也看不到「全部登記」。再到 Supabase 的 Advisors 確認沒有「RLS 未開啟」的警告。
    6. 
        
  6. 125–140 分用對話改成你的題目：不要自己打開檔案改，把第 03 段畫的表講給 Claude Code 聽（下面有範例），讓它動手、跟你解釋改了什麼，再 push。
    7. 
        
  7. 140–150 分自己驗收：用手機打開網站填一筆、用第二個帳號再測一次門禁、下載 CSV 看欄位對不對。有問題就把「看到什麼、預期是什麼」講給 Claude Code 修。
    8. 
      

      
照 CLAUDE.md 的規則，把這個登記系統改成「＿＿＿（你的題目）」：
- 表單欄位：＿＿（打字）、＿＿（下拉選單：＿／＿／＿）、＿＿（日期）
- 標題和說明改成：＿＿＿
- 先用規劃模式告訴我你要改哪些檔案，等我說好再改
- 改完用白話說明改了什麼，並告訴我要怎麼測試

      

      
AI 說「做好了」不算數，你測過才算（單元 01）。每改一次都要自己驗收：手機打得開、填得進去、第二個帳號看不到別人的資料、下載的 CSV 欄位是對的。

延伸挑戰．真正的 Vibe Coding
請 Claude Code 加一個範本沒有的功能

        
範本只是起點。挑一個你的題目真的需要的功能，自己把需求講清楚、讓 Claude Code 動手、自己驗收。這才是這門課要練的能力。

    

      
🧮 額滿就不能再登記
同一天超過 5 筆就擋下來。提示：這要改資料庫的規則（setup.sql），CLAUDE.md 會提醒 Claude Code 先跟你解釋誰多了、少了什麼權限。

      
🔎 管理者可以搜尋、篩選
管理者區加一個搜尋框和「只看待處理」的按鈕。只改網頁，不用動資料庫，最適合第一次挑戰。

      
🗓️ 我的登記照日期排序
「我的登記」照使用日期排，過期的變灰色。練習把「怎樣算完成」講清楚。

      
💡 你自己想的
用你第 03 段畫的表想一個：「如果多了＿＿，會更好用」。

    

    

      
怎麼開口（單元 03 的五個零件）

      
我想在登記系統加一個功能：＿＿＿（要做什麼）
- 給誰用：＿＿（管理者／登記的人）
- 限制：照 CLAUDE.md 的規則；要改 setup.sql 的話先用白話說明權限怎麼變，等我同意
- 怎樣算完成：＿＿＿（例如：同一天第 6 筆會跳出「這天已經額滿」）
- 先用規劃模式給我看計畫，一次只做一小步，每一步告訴我怎麼測

      

      
驗收三件事：① 新功能照「怎樣算完成」真的做到 ② 原本的功能沒被弄壞（登入、登記、門禁、匯出）③ 第二個帳號還是看不到別人的資料。
