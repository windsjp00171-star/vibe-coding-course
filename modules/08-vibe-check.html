08 C 資安．上線前檢查

AI 說「做好了」，
你要說「我檢查一下」

Vibe Check 就是上線前的健康檢查。AI 寫的程式常常「看起來能跑」，底下卻藏著漏洞。這個單元給你一套不用看懂程式碼也能做的檢查方法。

01
三層檢查

Vibe Check 不是一件事，是三道關卡

第一關

🙋 自己用一次

用手機、用電腦，像真正的使用者一樣從頭操作一遍。故意亂填、按兩次、中途關掉，看會不會壞。

第二關

🤖 請 AI 當稽核員

開一個新的對話，請 Claude Code 扮演資安稽核員，專門找問題、先不要修（第 05 段有現成指令）。

第三關

🔍 自動化掃描

用工具自動檢查密碼外流、危險寫法、有毒套件。第 03 段的體檢器就是簡化版的示範。

講師的真實經驗：一個已經上線、每週有人在用的小組回報系統，做了一次「全域稽核」，找到三個大問題：權限漏洞（不該看到的人看得到）、資料被默默洗掉、刪除帳號後整個網站當掉。這些問題平常用起來完全看不出來。

03
動手玩

AI 程式碼體檢器

選一段 AI 寫的程式，按「開始體檢」。你也可以直接修改程式碼，看看改了之後問題有沒有消失。

體檢報告會出現在這裡。

這個體檢器只認得幾種常見問題，目的是讓你知道「有工具可以幫忙抓」。真實專案可以請 Claude Code 幫你設定 GitHub 的自動掃描。

04
國際標準白話版

AI 應用的十大風險（OWASP 2025）

OWASP 是國際知名的資安組織，每隔一段時間整理「最常出事的風險清單」。這是它針對 AI 應用的 2025 年版，翻成白話。

05
上線前一定要做

上線前檢查表

每個專案上線前走一遍。勾選會記在瀏覽器裡。講師的專案裡就有一份類似的「上線前總檢查清單」。

    🤖 全域稽核指令

    開一個新對話，貼給 Claude Code：

    請你扮演資安稽核員，檢查這整個專案，先不要修改任何東西。
請逐一檢查並用白話回報：
1. 有沒有密碼、金鑰寫在程式裡，或被上傳到 GitHub
2. 每個頁面和功能，是不是只有「該看到的人」看得到
3. 使用者輸入的資料有沒有檢查（亂填、超長、特殊符號）
4. 刪除或修改資料時，會不會連帶弄壞其他東西
5. 錯誤訊息會不會洩漏系統內部資訊
6. 用到的套件是不是都真實存在、版本有沒有鎖住
最後依嚴重程度排序，列出問題、影響和建議的修法。

    課中．約 35 分　兩人一組，交換網址（和 GitHub repo，如果是公開的）。

    1. 0–10 分第一關：用手機打開對方的網站，照「上線前檢查表」的「使用者」段落實際操作，故意亂填亂按。
    2. 10–20 分第二關：在自己的專案用第 05 段的稽核指令跑一次，把 Claude Code 的報告存下來。
    3. 20–30 分把找到的問題寫在學習單上交給對方，每人挑一個最嚴重的，請 Claude Code 修好。
    4. 30–35 分全班分享：最意想不到的問題是什麼？
