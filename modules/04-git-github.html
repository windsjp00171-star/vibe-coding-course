04 B 上線．Git 與 GitHub

Git 是無限存檔點，
GitHub 是雲端保險箱

寫程式最怕的不是寫錯，而是「改壞了回不去」。這個單元不用背指令，只要搞懂幾個關鍵詞，你就看得懂 Claude Code 在幫你做什麼。

用 AI 寫程式時，這個問題會放大十倍：AI 一次可以改幾十個地方，改好了很棒，改壞了你根本不知道它動了哪裡。

Git 就像遊戲的存檔點。每次做到一個段落就存一次，每個存檔都附一句「這次做了什麼」。哪天改壞了，直接讀回上一個存檔點，不怕闖關失敗。
講師的真實數字：講師用 Claude Code 做的一個教會報名系統，半年內存檔超過 600 次，平均一天 3～4 次。每次只改一小塊，壞了就退回去。這就是 Vibe Coding 能做大專案的秘密。
02
最多人搞混的一件事

Git 和 GitHub 不是同一個東西

Git．在你的電腦裡

📷 手機裡的相簿

Git 是裝在你電腦裡的「存檔工具」。沒有網路也能存檔、也能讀回舊版本。但是電腦壞了、被偷了，存檔就跟著不見。

GitHub．在網路上

☁️ 雲端相簿（像 Google 相簿）

GitHub 是一個網站，幫你把存檔點備份到雲端。換電腦也拿得回來、可以分享給別人看、可以多人一起做，還能直接把網站「發佈上線」。

一句話記住：Git 負責「存」，GitHub 負責「放」。手機拍照（Git）→ 同步到雲端相簿（GitHub）。

    05
    好消息

    你不用背指令，跟 Claude Code 說人話就好

    Git 的指令很多，但你只要知道「想做什麼」。左邊這樣說，Claude Code 就會幫你執行右邊的指令。

    你對 Claude Code 說它做的事背後的指令（看得懂就好）
    「幫我存檔，說明寫清楚這次改了什麼」存檔 commitgit add．git commit
    「推上 GitHub」上傳 pushgit push
    「把 GitHub 上最新的版本拉下來」下載更新 pullgit pull
    「開一個新分支試做深色模式，不要動到 main」開分支 branchgit switch -c dark-mode
    「做好了，幫我開 PR」發合併請求 PRgh pr create
    「剛剛那次改壞了，退回上一個存檔」讀回存檔git revert
    「這個專案最近改了哪些東西？」看存檔紀錄git log
    小心這句話：「強制上傳」「把遠端蓋掉」（git push --force）會把 GitHub 上別人的修改直接覆蓋掉。Claude Code 要執行這種動作時會先問你，看不懂就按「拒絕」，再問它為什麼要這樣做。
    冷知識：用 Claude Code 桌面版或網頁版做事時，它常會自動開一個叫 claude/某某某 的分支，做完再請你合併。講師有好幾個專案的分支都是這個名字，這很正常，代表它有乖乖在平行世界裡工作。

    三個真實故事

    👯

    一模一樣的雙胞胎專案

    講師有兩個幾乎一樣的行政系統：一個是展示版，一個給教會實際使用。

    點我看發生什麼事 ↻
    教訓

    當初是整包複製一份。後來修好展示版的錯誤，卻忘了另一份也要修，兩份越差越多。

    學到：同一份程式要給不同地方用，應該用「設定檔」區分，不要複製成兩個 repo。

    三個空空的 repo

    講師的 GitHub 上有三個 repo 從建立到現在一次都沒存檔過。

    點我看發生什麼事 ↻

    🌏

    一萬次存檔的開源專案

    講師的 GitHub 上有一份 Taiwan.md，這是世界各地的人一起編寫的台灣知識庫。

    點我看發生什麼事 ↻
    Fork 與多人合作

    講師是用 fork，把別人的公開專案整包複製一份到自己帳號，可以隨意研究，不會影響原作者。這個專案累積超過一萬次存檔、一千多個 PR。

    學到：想幫別人的專案出力，就是 fork → 修改 → 發 PR 請原作者合併。

    07
    課中工作坊

    人體 Git：用便利貼演一次

    不用電腦。4 人一組，用便利貼和桌子把 Git 演出來。

    課中．約 25 分　準備：每組一疊便利貼、兩張 A4（一張寫「我的電腦」，一張寫「GitHub」）、一支筆。

    1. 0–3 分分配角色：開發者 A、開發者 B、GitHub 管理員（顧雲端那張紙）、記錄員（畫在學習單上）。
    2. 3–8 分A 在便利貼寫「存檔 1：做好標題」貼到「我的電腦」。問：GitHub 上有這張嗎？（沒有！）
    3. 8–12 分A 走過去把便利貼複製一張貼到 GitHub，這就是 push。
    4. 12–18 分B 也想改，先從 GitHub 複製一份到自己桌上（clone／pull），寫「存檔 2：改顏色」。B 想 push，但 A 已經先上傳了新的，管理員要拒絕，請 B 先 pull。
    5. 18–25 分A 拿另一種顏色的便利貼當「分支」，在旁邊試做新功能，做完寫一張「PR：請看我的新功能」交給 B 審核，B 同意後才合併到主線。
