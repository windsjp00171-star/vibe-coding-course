03 A 起步．合作

AI 很聰明，
但它讀不到你的心

同一個 Claude Code，有人做出好用的系統，有人做出一團亂。差別不在 AI，而在你怎麼交代、怎麼拆工作、怎麼留下規矩。這個單元是整門課最實用的一課。

  • 寫出有五個零件的好指令
  • 把大需求拆成一小步一小步
  • 寫出自己的 CLAUDE.md「員工手冊」
課前自學 約 25 分 課中工作坊 約 45 分 課後任務 約 20 分
▶
先玩再學．10 分鐘

同一個需求，講兩次看看差多少

模擬一次真實的交辦：先故意講得模糊，看 AI 做出什麼；再用五個零件重講一次。中間還會遇到「大改動要不要先規劃」和「修三次還不對怎麼辦」。

01
好指令的秘密

五個零件，缺一個就容易走歪

🎯 要做什麼

「做一個報名表」比「幫我弄一下」清楚一百倍。

🙋 給誰用

給 70 歲長輩用，和給工程師用，做法完全不同。

🚧 限制條件

「不要」和「只要」：只改這個檔案、手機要能用、不要用框架。

✅ 怎樣算完成

請它做完自己測一次，並告訴你怎麼確認。

🗺️ 先規劃再動手

請它先列步驟，你同意再開始。越大的需求越需要。

💡 記法

做什麼、給誰、限制、驗收、先規劃。跟交代新同事工作一模一樣。

🩺 指令健檢

寫一段你想對 Claude Code 說的話，看看五個零件齊不齊。

02
一次一小步

不要一口氣說「幫我做一個報名系統」

大需求一次丟給 AI，它會自作主張補一堆你沒說的東西。拆成小步，每步做完、試過、存檔，再做下一步。

講師的做法：一個報名系統存檔超過 600 次，每一次都只做一件事，例如「報名成功後寄確認信」「名額滿了要顯示候補」。每一步都小到 15 分鐘內能做完、測完。
判斷太大的訣竅：如果你沒辦法用一句話說出「怎樣算做完」，就代表還要再拆。
03
三種工作模式

你可以決定它要多「自動」

Claude Code 可以切換不同的權限模式。名稱和位置可能隨版本調整，概念是一樣的。

新手建議

🗺️ 規劃模式（Plan）

只研究、只提計畫，完全不動手。你看過計畫、說「可以」，它才開始做。大改動前一定先用。

預設

🙋 每次詢問

每次修改檔案或執行指令前，都先問你。慢一點，但每一步你都看得到。

熟練後

⚡ 自動接受修改

改檔案不再一個一個問，但執行指令還是會問。等你熟悉了、也有存檔習慣，再考慮開。

有一種模式叫「略過所有權限」：它什麼都不問就直接做。新手請不要開。單元 7 會說明為什麼。

終端機版用 Shift＋Tab 切換模式；桌面版在輸入框附近可以選。

04
給 AI 的員工手冊

CLAUDE.md：寫一次，每次都照做

每次開新對話，Claude Code 都會先讀專案資料夾裡的 CLAUDE.md。把你的規矩寫進去，就不用每次重講。

就像新同事報到第一天拿到的員工手冊：公司的習慣、不能碰的東西、做完要怎麼回報，寫清楚，大家都省事。

📍 這個檔案要放在哪裡？

  • 檔名就是 CLAUDE.md（全部大寫，副檔名 .md）
  • 放在專案資料夾的最外層——就是你在 Claude Code 裡選的那個資料夾，跟 index.html 放在一起
  • 不用自己開檔案總管：最簡單的方式是把內容貼給 Claude Code，說「請把下面的內容存成這個專案的 CLAUDE.md」，它會自己建好
  • 要確認它讀到了，就開一個新對話問：「你讀到哪些規矩？」

🌍 兩種範圍，可以同時用

專案版全域版（進階）
放哪裡專案資料夾最外層你的個人資料夾 ~/.claude/CLAUDE.md
套用範圍只有這個專案你電腦上的每一個專案
適合寫這個專案的規矩、給誰用、用什麼技術你個人的習慣：回報格式、commit 訊息寫法

先做專案版就好。全域版等你有好幾個專案、發現自己一直重複交代同樣的事，再來寫。

講師自己的 CLAUDE.md 守則（白話版）

這是講師所有專案共用的規矩，每一條都是踩過坑換來的。點卡片看原因。

05
動手做

產生你的第一份 CLAUDE.md

填好、勾選，複製下來貼給 Claude Code，請它存成專案裡的 CLAUDE.md。

要放哪些規矩？

        

        
貼給 Claude Code 時就說：「請把下面的內容存成這個專案的 CLAUDE.md」，它會建在專案資料夾最外層。存好之後開一個新對話問它「你讀到哪些規矩？」，確認真的生效。

      

    

  


  

    
06
      
交接的藝術
AI 會「失憶」，所以要留紙條

        
對話太長時，Claude Code 會把前面的內容壓縮成摘要，細節可能就不見了。開新對話更是從零開始。

    

      
📍 收工紙條（Session Snapshot）
講師的守則要求 Claude Code 每次收工都寫一張固定格式的紙條，下次開新對話直接貼上：

        
📍 Session Snapshot — 報名表
上次做到：完成報名成功後的確認畫面
目前狀態：可以運行
卡點：候補名單的規則還沒決定
下一步：寫「名額滿了顯示候補」
需要注意：不要改動 data/ 資料夾

      
📦 把坑打包成工具包
講師做「LINE 登入＋裝到手機桌面」時，前後踩了十個不會報錯、但使用者那邊是壞的的坑。例如：裝好 App 打開後，被要求輸入 LINE 的 Email 和密碼，然後就卡住了。

        
後來講師請 Claude Code 把整套做法和十個坑寫成一份交接文件。下一個專案要加同樣功能時，直接把文件交給新對話：「先讀這份，照著做，做完逐條驗收」。同樣的坑不用再從頭摸索一次。

        
這個故事在選修單元 13 會完整拆解。
