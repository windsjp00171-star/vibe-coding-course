05 B 上線．部署

從自家廚房
到開一家店

你電腦上的網頁，只有你看得到。「部署」就是把它搬到網路上的主機，給別人一個網址就能打開。這個單元教你選平台、搬上去，以及搬家時最常踩的坑。

  • 分得出靜態網站和動態網站
  • 依照需求選一個合適的上線平台
  • 把自己的網頁用 GitHub Pages 上線
課前自學 約 20 分 課中工作坊 約 35 分 課後任務 約 15 分
▶
先玩再學．10 分鐘

主管說「傳給我看」，你要怎麼給？

模擬把作品放上網路的整個過程：選平台、第一次上線、遇到 404、改一行再上線。大約 10 分鐘。

01
先講概念

部署是什麼？

自家廚房（本機）：你做的菜只有家人吃得到。Claude Code 幫你開的預覽網址像 localhost:5173，意思是「這台電腦自己」，別人打不開。
開一家店（部署）：把菜單和廚房搬到大街上的店面（網路主機），給大家一個地址（網址），誰都能來。

整個流程只有三步

  1. 在自己電腦做好、測好
  2. push 上 GitHub（單元 4 學過）
  3. 上線平台自動從 GitHub 抓下來，給你一個網址

設定好之後，以後每次 push，網站就會自動更新。這就是為什麼要先學 GitHub。

02
最重要的分類

靜態網站 vs 動態網站

選平台之前，先分清楚你做的是哪一種。

靜態網站

🖨️ 印好的傳單

每個人看到的內容都一樣，網站不用「記住」任何東西。作品集、活動介紹、課程網站（就是你現在看的這個）。

上線：免費、簡單。

動態網站

🧑‍💼 有店員的櫃台

要存資料、要登入、每個人看到的不一樣。報名系統、會員系統、LINE 機器人。後面需要一台一直開著的主機和資料庫。

上線：要多設定，可能要付費。

04
最簡單的上線

用 GitHub Pages 上線（免費）

適合靜態網站。這個課程網站就是這樣上線的。

在你的專案資料夾對 Claude Code 說：

請幫我把這個網站用 GitHub Pages 上線：
1. 先確認已經 push 到我的 GitHub repo
2. 用 gh 指令開啟 GitHub Pages，來源選 main 分支的根目錄
3. 等它建置完成，給我網址，並確認網址打得開
每一步做之前先告訴我要做什麼。

注意：免費帳號的 GitHub Pages 需要 repo 設成 Public（公開）。所以絕對不能有密碼在裡面（單元 6）。

  1. 打開你在 GitHub 上的 repo確認網站檔案已經 push 上去，而且首頁檔名是 index.html。
  2. 點上方的「Settings」再點左邊選單的「Pages」。
  3. 在「Branch」選 main，資料夾選 / (root)，按 Save等一到兩分鐘。
  4. 重新整理頁面，上方會出現網址格式是 https://你的帳號.github.io/repo名稱/
  5. 用手機打開這個網址在別的裝置能打開，才算真的上線成功。
05
動態網站才需要

環境變數：店長手機裡的保險箱密碼

動態網站要連資料庫、要用 LINE 登入，需要各種密碼和金鑰。可是密碼不能放在 GitHub 上，那上線的網站要去哪裡拿密碼？

答案：寫在平台後台的「環境變數」。就像店裡保險箱的密碼記在店長手機裡，而不是貼在店門口。程式只寫「去問店長」（process.env.資料庫密碼），真正的密碼只存在平台上。

三個地方，三種放法

你的電腦.env 檔（已經放進 .gitignore，不會上傳）
GitHub完全不放密碼，只放 .env.example 範本（只有名稱沒有值）
上線平台後台的 Environment Variables 設定頁

講師的每個動態專案都有 .env.example，告訴下一個人需要哪些密碼，但不給值。

06
講師踩過的坑

四個真實的部署故事

點卡片看發生什麼事、怎麼解決。

🚚

搬家後，中文網址全壞了

讀經網站從一個平台搬到另一個平台，英文頁面都正常，可是所有中文書卷的網址都顯示「查無此章經文」。

點我看解法 ↻
原因

兩個平台處理「網址裡的中文字」的方式不一樣，新平台送進來的是編碼過的亂碼。

學到

換平台不是按一下就好。搬家後要把每一種網址都點過一次，特別是有中文、有特殊符號的。

🪪

部署一直失敗，連試四次

一個記帳系統的程式明明沒問題，推上去卻一直部署失敗。存檔紀錄裡連續出現四次「用不同身分重新觸發部署」。

點我看解法 ↻
原因

上線平台會檢查「是誰存檔的」。存檔者的帳號跟平台的專案擁有者對不上，平台就拒絕部署。

學到

部署失敗時，先打開平台的錯誤紀錄（log），整段複製貼給 Claude Code：「這是部署錯誤，請用白話說明原因」。不要瞎猜。

📦

什麼都沒改，網站自己壞了

PitchPal 放在 Hugging Face 上好好的，某天突然啟動不了，卡在載入畫面。

點我看解法 ↻
原因

程式用到的套件自己升級了新版本，新版改了用法，舊程式就壞了。

學到

請 Claude Code 把套件版本鎖住（寫死版本號）。你沒有改，不代表別人沒有改。

😴

第一個人打開要等 30 秒

檔案分享平台放在免費主機上，早上第一個打開的人總是要等很久，還以為網站壞了。

點我看解法 ↻
原因

免費主機沒人用一段時間就會「睡著」省資源，有人來才會慢慢叫醒。

學到

用免費的定時服務每隔幾分鐘「戳」它一下保持清醒，或是給重要的系統付一點錢升級。免費的東西都有代價。
