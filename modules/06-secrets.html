半夜收到一封信：你的金鑰被盜用了

模擬金鑰外洩的那 30 分鐘：找出問題、決定第一步做什麼、把程式改對。這一關的順序判斷，比記住指令更重要。大約 10 分鐘。

01
認識鑰匙

API 金鑰：一張不用密碼的信用卡

你的網站要用 AI、寄信、傳 LINE、連資料庫，都要向這些服務證明「我是付錢的那個人」。證明的方式就是一串很長的字，叫做金鑰（API Key），長得像這樣：

sk-proj-7f3a9c...（後面還有幾十個字）

金鑰＝信用卡號＋門禁卡。誰拿到它，誰就能用你的名義花錢、讀資料、發訊息。服務商不會知道是不是你本人在用。

金鑰外流會發生什麼事？

  • 💸 AI 服務被拿去狂用，帳單一夜爆表
  • 📂 資料庫被讀光，會員個資外洩
  • 📨 你的 LINE 官方帳號被拿去發詐騙訊息
  • 🗑️ 最糟的情況：資料被全部刪除

網路上有程式 24 小時在掃描 GitHub 的公開專案，專門找這種字串。

02
收好鑰匙

.env 與 .gitignore：鑰匙盒和禁帶清單

🔐 .env＝鑰匙盒

專案資料夾裡一個叫 .env 的檔案，所有密碼、金鑰都放這裡。程式裡只寫「去鑰匙盒拿」，不寫真正的值。

OPENAI_API_KEY=sk-proj-這裡放真的金鑰
DATABASE_URL=這裡放資料庫密碼

🙈 .gitignore＝禁帶清單

告訴 Git「這些檔案永遠不要存檔、不要上傳」。.env 一定要在清單上。

.env
.env.*
node_modules/

另外放一個 .env.example，只寫名稱不寫值，告訴別人需要哪些鑰匙。

動手找

找出藏在程式裡的鑰匙

AI 為了讓程式「馬上能跑」，有時會把金鑰直接寫進程式碼。點出有問題的那一行。

04
萬一掉了

不小心把金鑰上傳了，怎麼辦？

最常見的錯誤：以為「把檔案刪掉再上傳一次」就好。
沒用！Git 會保留每一次的存檔紀錄，舊的存檔裡還看得到金鑰。唯一有效的做法，是到服務商的後台把那把鑰匙作廢，換一把新的。
就像鑰匙掉了，要做的是換鎖，不是把掉鑰匙的地方掃乾淨。

好消息：GitHub 對公開專案有「秘密掃描」功能，偵測到常見的金鑰格式時會擋下上傳或通知你。但不要依賴它，它不認得所有種類的密碼。

05
另一種外流

哪些東西不能貼給 AI？

不只是程式碼，你貼進 AI 對話框的每一句話，都會送到別人的伺服器上。公司沒核准的 AI 用法，叫做「影子 AI（Shadow AI）」。

這門課自己就是例子：講師的專案大多是教會內部系統，有會友資料。所以教材裡的案例全部匿名化：不寫單位名稱、不放網址、不放程式碼。分享經驗和保護資料可以同時做到。

下面是時間表，講師會在每一段開始前說一次。跟不上也沒關係，重點是做出上面那個產出。

課中．約 30 分

  1. 0–10 分對自己的 Claude Code 說：「請檢查這個專案，有沒有密碼、金鑰、個資被寫在程式裡，或已經被上傳到 GitHub。用白話列出來，先不要改。」
  2. 10–15 分確認專案裡有 .gitignore，而且裡面有 .env。沒有就請它加上。
  3. 15–25 分兩人交換，打開對方在 GitHub 上的 repo 網頁，用眼睛找有沒有看起來像密碼的東西。
  4. 25–30 分全班分享：有沒有人找到？（找到不丟臉，找到才能換鎖。）
